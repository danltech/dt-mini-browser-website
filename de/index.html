Warum DT Mini Browser?

Die meisten „leichten“ Android-Browser bringen trotzdem noch ein volles WebView oder Gecko mit. DT Mini Browser geht einen anderen Weg: Das Handy zeichnet nur, der Server macht die schwere Arbeit.

So funktioniert's

Eine klassische Thin-Client-Architektur – aktualisiert für das moderne Web.

1

Du betreibst den Server

Auf einem Linux-Rechner, Raspberry Pi, Windows-PC oder in Docker. Der Server startet einen headless Chromium und stellt eine kleine JSON-API bereit (Standard-Port 8080).

2

Handy verbindet sich per QR oder Adresse

Beim ersten Start erzeugt der Server ein Token, optional ein selbstsigniertes Zertifikat und einen QR-Code. Diesen in der App scannen oder den Setup-Text einfügen. Der Client speichert Server-URL + Token.

3

Server rendert, Client zeichnet

Beim Öffnen einer URL lädt der Server die Seite in echtem Chromium, extrahiert das fertige Layout in eine kompakte Display-Liste (Rechtecke, Textzeilen, Bilder, Link-Flächen, Formularfelder) und schickt sie als gzip-JSON. Die Android-App malt sie nur noch – kein WebView nötig.

4

Interaktion bleibt flüssig

Taps, Tippen und Zurück-Navigation werden als einfache Befehle geschickt. Der Server aktualisiert den Seitenzustand und liefert eine neue Display-Liste. Bilder werden bei Bedarf angefordert und stark komprimiert.

// Vereinfachter Ablauf Handy ──GET /load?url=…&w=360&h=640──▶ Server (Chromium + Playwright) Handy ◀── gzip-JSON Display-Liste ──── Server Handy ──GET /tap?sid=…&x=120&y=340───▶ Server Handy ◀── aktualisierte Display-Liste ─ Server Handy ──GET /img?sid=…&id=42&tw=320──▶ Server (JPEG, verkleinert)

⚠ Sicherheit & Privatsphäre – bitte lesen

  • Es gibt keine offiziellen öffentlichen Server. Wer einen „öffentlichen DT-Mini-Browser-Server“ anbietet, hat nichts mit dem Projekt zu tun.
  • Der Server sieht alles, was du browsest – inklusive Formulardaten, in Seiten eingegebene Passwörter und Cookies.
  • Betreibe den Server nur auf Hardware, die du kontrollierst, oder für Personen, die dir vollständig vertrauen.
  • Bevorzuge HTTPS + Token + VPN (WireGuard / Tailscale) oder einen Reverse-Proxy. Öffne Port 8080 nicht einfach ins Internet.
  • Aktiviere niemals MINI_ALLOW_PRIVATE=1 auf einem Server, den andere erreichen können (deaktiviert den Schutz vor internen Netzwerken).
  • Lesezeichen und Verlauf bleiben auf dem Gerät. Die App verlangt nur die INTERNET-Berechtigung (plus Speicher für Downloads auf älteren Android-Versionen).
