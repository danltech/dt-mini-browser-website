Why DT Mini Browser?

Most “lightweight” Android browsers still ship a full WebView or Gecko. DT Mini Browser takes a different approach: the phone only draws, the server does the hard work.

📱

Runs on ancient phones

minSdk 16 (Android 4.1 Jelly Bean). Pure Java, no AndroidX, no Kotlin, no WebView. Tiny APK.

🌐

Real modern web

Server uses real headless Chromium via Playwright. Full JavaScript, CSS, images, forms and complex layouts work.

🛡️

Ads & trackers blocked server-side

DoubleClick, Google Analytics, Taboola, Facebook, Criteo and many more are filtered before they reach the client.

⚡

Bandwidth friendly

Images are downscaled and JPEG-compressed on the server. Only a compact display list is sent to the phone.

🔒

You control the data

Bookmarks and history stay on the device. No analytics, no accounts, no phone-home. You decide where the server runs.

🌍

Many languages

Client UI: English, German, Spanish, French, Italian, Turkish, Russian, Japanese, Simplified Chinese.

How it works

A classic thin-client architecture – updated for the modern web.

1

You run the server

On a Linux machine, Raspberry Pi, Windows PC or in Docker. The server starts a headless Chromium and exposes a small JSON API (port 8080 by default).

2

Phone connects via QR or address

On first start the server creates a token, optional self-signed certificate and a QR code. Scan it in the app or paste the setup text. The client stores the server URL + token.

3

Server renders, client draws

When you open a URL the server loads the page in real Chromium, extracts the finished layout into a compact display list (rectangles, text runs, images, link areas, form fields) and sends it as gzip JSON. The Android app only paints it – no WebView required.

4

Interaction stays responsive

Taps, typing and back-navigation are sent as simple commands. The server updates the page state and returns a new display list. Images are requested on demand and heavily compressed.

⚠ Security & Privacy – please read

  • There are no official public servers. Anyone offering a “public DT Mini Browser server” is not affiliated with the project.
  • The server sees everything you browse – including form data, passwords typed into pages, and cookies.
  • Only run the server on hardware you control, or for people who fully trust you.
  • Prefer HTTPS + token + VPN (WireGuard / Tailscale) or a reverse proxy. Do not simply open port 8080 to the internet.
  • Never enable MINI_ALLOW_PRIVATE=1 on a server that others can reach (disables internal-network protection).
  • Bookmarks and history stay on the device. The app only requests the INTERNET permission (plus storage for downloads on older Android).
